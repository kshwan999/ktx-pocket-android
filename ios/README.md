# KTX 자리찾기 — 아이폰 실행 시험 버전

**실제 코레일 조회·예약을 연결하기 전, 아이폰 단독 실행이 유지되는지 측정하는 1차 개발 버전입니다.** 계정과 비밀번호를 받지 않으며, 외부 통신이나 예약 요청을 보내지 않습니다. 이 프로젝트의 안드로이드 앱과 기능 범위가 다릅니다.

## 지금 사용할 수 있는 기능

- 출발역·도착역·출발 시간 범위·어른 1~6명·좌석 종류 입력
- 현재 조건과 직접 추가한 대안 최대 2개 기억
- 같은 출발지에서 각 역까지 걸리는 시간을 직접 입력해 출발역 대안 계산
- 직접 입력한 조건을 먼저 포함하고, 이동 시간이 짧은 자동 대안을 더해 전체 최대 3개로 제한
- 이동 시간·추가 이동 허용·승차 여유를 반영한 후보 미리보기
- 확인한 조건을 고정하고 **1·5·15·30분 동안 실행 간격 측정**
- 3~5초마다 측정 시각·경과 시간·앱 화면 상태를 기록하고 가장 긴 실행 공백 표시
- 앱의 중지, iOS의 실행 시간 회수, 재실행 때 발견한 이전 실행 중단을 구분
- 시험 완료·중단 알림, 예정된 시험 시간이 지난 뒤 기록을 확인하라는 보조 알림
- 최근 시험 기록을 파일로 직접 공유하거나 삭제

알림 권한을 거절해도 측정할 수 있지만 결과는 앱에서 직접 확인해야 합니다. 운영체제·집중 모드 등에 따라 알림이 늦거나 표시되지 않을 수 있습니다.

## 맥에서 실행하기

필요한 환경은 **Xcode 26.2 이상을 실행할 수 있는 맥과 iOS 26 이상인 아이폰**입니다. 백그라운드 실행 여부는 실제 아이폰에서 확인해야 합니다. 시뮬레이터로 설치 화면을 볼 수는 있지만 기기의 잠금·절전·실행 제한을 검증할 수 없습니다.

1. 저장소를 내려받고 `ios/KTXPocket.xcodeproj`를 Xcode로 엽니다.
2. 앱 대상 `KTXPocket`의 **Signing & Capabilities**에서 본인의 개발 팀을 선택합니다. 작업 식별자는 앱 식별자에서 자동으로 만들어집니다.
3. 아이폰을 연결하고 실행 기기로 선택합니다. 필요하면 기기의 개발자 모드를 켜고 맥을 신뢰하도록 설정합니다.
4. Xcode의 실행 버튼으로 설치합니다. 별도 서버 주소나 텔레그램 토큰은 필요하지 않습니다.

윈도우에서는 Xcode로 아이폰 앱을 만들거나 서명할 수 없습니다. 이 저장소의 자동 검사는 깃허브의 맥 환경에서 수행하며, **서명 없는 빌드 결과나 시뮬레이터용 앱을 아이폰에 바로 설치할 수는 없습니다.** 기기 설치에는 본인의 개발 팀으로 서명해야 합니다. 앱스토어·테스트플라이트 배포는 아직 구성하지 않았습니다.

## 실행 시험 방법

1. 여행 조건을 입력합니다. 날짜·시간은 한국시간 기준입니다.
2. 다른 출발역도 괜찮다면 역별 이동 시간을 등록하고 추가 이동 허용 시간과 승차 여유를 정합니다. 실제 이동 시간은 지도 앱 등에서 확인해 직접 입력합니다.
3. 먼저 1분 또는 5분을 선택하고 **조건 확인하고 실행 시험**을 누릅니다.
4. 확인 창에 표시된 조건을 확인하고 시험을 시작합니다. 알림 권한을 요청하면 원하는 대로 선택합니다.
5. 상태가 **실행 간격 측정 중**으로 바뀐 것을 확인한 뒤 홈 화면으로 나가거나 아이폰을 잠급니다.
6. 정한 시간 뒤 앱에 돌아와 화면 밖 실행 표본 수, 최대 실행 공백, 10초 초과 간격 수를 확인합니다. 필요하면 기록 파일을 공유합니다.
7. 짧은 시험 후 15분·30분으로 늘려보고, 저전력 모드·잠금 상태·다른 앱 사용 상태에서 각각 비교합니다.

기록 공유 파일에는 여행 조건과 실행 시각이 들어 있습니다. 공유 대상을 확인해주세요. 계정·비밀번호·통신 응답은 들어 있지 않습니다.

## 결과를 읽을 때 주의할 점

- 진행률은 **실제 관측한 경과 시간**입니다. 열차 검색 진행률이나 예약 성공 확률이 아닙니다.
- 앱 화면에서만 실행했다면 백그라운드 동작을 확인한 것으로 표시하지 않습니다.
- 10초를 넘는 기록 간격은 별도로 표시합니다. 이 값은 진단용 기준이며 코레일이나 애플의 공식 허용 기준이 아닙니다.
- 시스템 시계가 바뀌어도 간격이 잘못 계산되지 않도록 기기의 단조 증가 시간을 사용합니다. 사람이 읽는 시각은 별도로 기록합니다.
- 시험이 정상 종료돼도 실제 통신 부하·예약 요청·몇 시간 동안의 실행을 보장하지 않습니다. 현재 버전은 네트워크 요청을 보내지 않습니다.
- iOS가 작업을 허용하지 않으면 시작 실패를 표시합니다. 나중에 몰래 시작하지 않도록 즉시 시작할 수 없는 요청은 실패시키는 방식을 사용합니다.
- 시스템이 작업을 중단하면 가능한 범위에서 기록을 저장하고 알립니다. 자동 재시작하지 않습니다.
- 앱을 강제 종료했거나 프로세스가 갑자기 사라지면 중단 알림을 직접 보낼 수 없습니다. 다음 실행 때 미완료 기록을 발견하면 중단 상태로 표시하며, 정확한 종료 시각과 원인은 추정하지 않습니다.
- 시험 시작 때 예약하는 보조 알림은 ‘예정 시간이 지났으니 기록을 확인하라’는 안내입니다. 실제 완료나 중단을 판정하는 알림이 아닙니다.

조건과 최근 시험 기록은 아이폰 내부에 저장하고 백업에서 제외합니다. 기기를 잠근 뒤에도 기록을 쓸 수 있도록 첫 잠금 해제 이후 접근 가능한 파일 보호 방식을 사용합니다. 한 번에 시험 하나만 실행하고 최근 기록 하나만 보관합니다. 새 시험을 시작하면 이전 기록을 덮어쓰므로 필요한 기록은 먼저 공유해 저장해주세요.

## 개발 구조와 검사

- `KTXPocket/`: 아이폰 화면, 백그라운드 작업 수명 관리, 파일 저장, 알림
- `Core/`: 플랫폼과 분리한 조건 검증·후보 계산·측정 기록·중단 처리 및 단위 검사
- `KTXPocket.xcodeproj`: 추가 생성 도구 없이 열 수 있는 Xcode 프로젝트
- `../.github/workflows/ios-check.yml`: 맥에서 단위 검사, 시뮬레이터용 빌드, 서명 없는 아이폰용 빌드

추가 외부 프레임워크는 사용하지 않습니다. 화면은 SwiftUI, 실행 작업은 `BGContinuedProcessingTask`, 알림은 애플의 알림 기능으로 구성했습니다. 계정 저장·코레일 통신·결제 재알림은 이번 아이폰 버전에 연결하지 않았습니다.

맥에서 단위 검사:

```sh
swift test --package-path ios/Core
```

저장소 루트에서 시뮬레이터용 앱 만들기:

```sh
xcodebuild -project ios/KTXPocket.xcodeproj -scheme KTXPocket \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath ios/build/simulator CODE_SIGNING_ALLOWED=NO build
```

검사 결과는 저장소의 **Actions → iOS prototype checks**에서 확인합니다. 자동 검사가 통과해도 실제 기기의 화면·알림·잠금 상태 실행을 확인한 것은 아닙니다.

애플의 [장시간 작업 문서](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados)와 [백그라운드 실행 설명](https://developer.apple.com/videos/play/wwdc2025/227/)을 기준으로 구성했습니다. 이 API는 사용자가 직접 시작한 유한한 작업을 위한 기능입니다. 빈자리 감시 용도로 적합한지는 실제 기기 결과와 애플의 정책을 함께 검토해야 하며, 앱스토어 심사 통과를 가정하지 않습니다.
